# libmpv runtime

Run `powershell -ExecutionPolicy Bypass -File scripts/Get-Mpv.ps1` from the project root to obtain the pinned Windows x64 runtime. The archive and extracted SDK are cached in `D:\tools\mpv\20261013`; the script verifies the archive SHA-256 before extracting it with Windows' built-in `tar.exe`.

The upstream library is named `libmpv-2.dll`. It is copied here as `mpv-2.dll` to match the application's P/Invoke library name. The binary is excluded from source control and copied into build/publish output by the desktop project. No additional DLLs are present in this upstream development archive.

The current native player uses mpv's `wid` API, D3D11 video output, `hwdec=auto-safe`, and mpv/libass subtitle rendering. mpv falls back to software decoding for formats that cannot use hardware decoding. This is the baseline x86_64 build, not the AVX2/x86_64-v3 build.

`MpvPlayer` posts events to the `SynchronizationContext` captured during construction, which should be the WPF dispatcher. `NativeVideoHost.AttachPlayer(player)` bridges `PointerInput`, `ShortcutInput`, and `FilesDropped`. WPF handles keyboard shortcuts when it has focus; explicit mpv bindings forward the same shortcuts when the native child window has focus. mpv's default bindings are disabled. Built-in drag-and-drop loading is disabled; dropped local paths are forwarded to the application to update its queue and history.

Left-button input and the unmodified Right arrow use mpv's native `script-binding` client-message protocol, which carries down, up, repeat, and cancellation states without loading a script. `PointerInput` forwards actual left-button down/up events; `TemporarySpeedRequested` forwards Right-arrow down as `true` and up/cancel as `false`. The UI owns temporary 3x speed and restores its selected speed on release or loss of application focus. Standalone mpv window dragging is disabled so it cannot consume clicks on the embedded video surface. Ordinary shortcuts retain the simpler `script-message` protocol.

On Windows, mpv intentionally disables its embedded child window (`EnableWindow(child, 0)` in its `--wid` path). Physical pointer hit-testing must therefore land on `NativeVideoHost`, not on mpv. The host registers a non-transparent Win32 class with `CS_DBLCLKS`, forwards its real mouse messages to WPF, and returns `MA_ACTIVATE` so a video click activates the application. A plain Win32 `STATIC` host without `SS_NOTIFY` is transparent to mouse hit-testing; posting messages to mpv's disabled child bypasses this behavior and is not a valid physical-click test. The native input probe checks that mpv's child is disabled and the host responds with `HTCLIENT`.

Sidecar subtitles are managed by the application (`sub-auto=no`). Await `AddSubtitleAsync(path, expectedGeneration)` to obtain the exact subtitle track ID after loading; it returns null when the file was replaced. It checks/enqueues atomically against `Load()` and relies on mpv's playback-coupled cancellation to stop an in-flight subtitle load on file replacement.

Commands and property writes are asynchronous; `CommandAsync` completes on the matching native command reply. Short synchronous property reads support UI polling. `FileLoadedDetailed` and `PlaybackEndedDetailed` include the path, load generation, and native playlist entry ID; IDs from `loadfile` replies and `start-file`/`end-file` events associate each callback with the correct file. Superseded generations are suppressed. `CurrentPath` is the last confirmed loaded path; `RequestedPath` is the latest request. `ErrorOccurred` reports media load or native event-loop failures; `NonFatalErrorOccurred` reports ordinary fire-and-forget command/property failures. Awaited commands return their errors through the task. Disposal wakes the event thread and lets that thread terminate mpv so the WPF thread remains available while native windows are destroyed.
